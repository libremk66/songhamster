# 歌单同步重设计 · 定稿规格(Phase A 完成,编码依据)

> 状态:UI 原型 `/sync-designer` 交互已验收(2026-09-07)。本文档是 Phase B/C 编码的唯一依据。
> 术语:源 = LX 歌单;目标服务器 = Emby/Navidrome/Subsonic/道理鱼/Jellyfin(下称 target)。

---

## 1. 目标与范围

把"同步"语义从二分(`增量|完全`)升级为 **增量 | 镜像**,并把任务创建与自动化监听重组为两标签 IA:

- 标签1:单任务创建(一个 LX 歌单 → 一个同步任务)
- 标签2:监听同步(自动化:完全 / 条件增量,二选一互斥)

引擎改动只涉及:歌单条目增删处理、自动建任务逻辑、历史记录;下载/打标/洗版等能力不动。

## 2. 同步语义(核心)

### 2.1 增量(incremental)
LX 端新增歌曲 → 同步到 target;LX 端删除歌曲 **不** 同步。target 该歌单只增不减。

### 2.2 镜像(mirror,替代旧 `full`)
LX 增/删都同步到 target(播放列表/歌单维度向 LX 看齐)。旧 `syncMode:'full'` 等价于"镜像 + 删除处理1"。

### 2.3 镜像下 LX 删除时的处理策略(delPolicy,三级)

| 值 | 含义 | 能力约束 |
|---|---|---|
| `keep`(默认) | 歌曲从目标播放列表移除;媒体库文件不删 | 所有服务器 ✅ |
| `delete` | 歌曲从播放列表移除 + 媒体库文件删除 | **仅 Emby/Navidrome**(文件在本项目映射目录内才可删,先移入 `.songferry-trash` 可恢复);道理鱼(REST 只增不减)/Subsonic(无路径)= 该选项置灰 |
| `archive` | 从原播放列表移除 + 加入归档歌单(默认名 `歌单同步任务归档`,可配) | 所有服务器 ✅(需能建播放列表并加曲;按歌曲 key 去重,防归档重复) |

能力矩阵以"当前 target"渲染时置灰不可选的策略,并存进任务记录。

## 3. 所有权追踪(镜像 + 已有播放列表的安全底线)

镜像删除**绝不做整单 diff**(会误删用户手动加的歌)。规则:

1. **provenance**:每次同步落库记录"歌曲条目由哪首 LX 歌、哪个任务加入目标歌单"
2. 镜像移除时**只删 provenance 归属本任务的条目**;目标歌单里用户自加/接管前已存在的歌不动
3. **接管语义**:任务绑定已有播放列表的瞬间做基线快照(快照前存在 = 非我所有)
4. 同 LX 歌单不得被两个任务映射到同一"已有播放列表"(创建时校验)
5. 目标歌单被用户删除 → 同步时探测缺失,按策略**自动重建同名歌单**或**跳过+告警**(默认重建+通知),不静默出错
6. UI 提示:勾选"已有播放列表"+镜像时显示所有权说明条(原型已验证)

## 4. 监听同步(标签2)设计

### 4.1 模型:单监听器 + 模式互斥

完全同步与条件增量监听同一事件源(新 LX 歌单),**不能并存**。建模:

```yaml
listen:
  enabled: bool          # 总开关
  activeMode: all | filtered
  checkCron: "0 7 * * *" # 检测周期(轮询 lxserver 歌单列表)
  all:      { 目标/方式/删除策略/新任务 cron }   # 模式参数分开保存,切换不丢
  filtered: { rules, 目标/方式/删除策略/新任务 cron }
```

### 4.2 模式切换任务策略(定稿:A + C)

- **默认保持**:切换只影响"之后新出现"的歌单;旧模式已自动创建的任务保持运行,绝不静默暂停/删除
- **切换询问**:切换时若旧模式有运行中的任务(origin 组),弹确认条:[保持运行(默认,推荐)] / [暂停旧模式任务]
- **可恢复**:暂停任务在切回原模式时显示 [恢复它们];恢复同入口;删除只能用户手动
- **origin 标记**:自动创建的任务打 `origin: auto-all | auto-filtered`,支撑上述分组操作与统计

### 4.3 条件增量规则(rules)

- 排除(exclude):命中 → 不同步。条件 = ①选择现有歌单 ②歌单名关键词(可多词,逗号分隔)
- 匹配(match):命中 → 同步。条件同上
- 语义:同时启用 = 先排除再匹配(白名单交集外再剔除);只开匹配 = 仅命中项;只开排除 = 全量减排除项
- 规则变更**不回溯**:只影响之后新出现的歌单(防误伤已建任务)

### 4.4 基线

首次启用记录当前 LX 歌单全集为基线,之后新出现者按 activeMode+规则评估建任务(沿用现有 autoadd baselineDate 机制)。

## 5. 旧配置迁移(兼容不漂移)

| 旧 | 新 |
|---|---|
| `syncMode:'full'` 的任务 | `mode:'mirror'` + `delPolicy:'keep'` |
| `syncMode:'incremental'` 任务 | `mode:'incremental'` |
| autoadd 旧配置(enabled/checkCron/baselineDate/默认设置) | `listen.all` 对应字段 + `activeMode:'all'` |
| 已建任务不含 origin | 存量任务 `origin: manual`(不参与分组统计) |

## 6. UI 映射

- `/sync-designer` 原型定稿 → 并入正式页(建议替换 sync-setup 的手动/自动新增两卡为两标签结构;任务列表/进度等页面不动)
- 菜单项"歌单同步"不变;标签2 中监听配置从旧 autoadd 卡迁移
- 删除处理2 置灰逻辑:按当前 target 能力渲染

## 7. 验收清单(Phase D 回归用)

- [ ] 增量任务:LX 加歌 → target 加;LX 删歌 → target 不动
- [ ] 镜像+keep:LX 删歌 → 目标播放列表移除该曲,文件保留;目标歌单中用户自加的歌不被删(provenance)
- [ ] 镜像+delete(Emby/Navidrome):文件进回收站可恢复;道理鱼/Subsonic 该选项不可选
- [ ] 镜像+archive:被删歌曲进归档歌单,重复 key 不叠加
- [ ] 目标已有歌单被删 → 自动重建(或告警)且不崩溃
- [ ] 监听:完全/条件互斥;切换确认条默认保持;暂停任务切回可恢复;规则变更不回溯
- [ ] 旧配置迁移后行为与迁移前一致(增量/全量任务语义不变)

## 8. 实施阶段

- Phase B:配置模型扩展(listen/mode/delPolicy/archive 名/rules/origin)+ 旧配置迁移 + DB provenance 字段
- Phase C:引擎 — 增量/镜像执行重构、delPolicy 三态、provenance 守卫、归档歌单适配器、监听器/规则评估、origin 任务管理 API
- Phase D:回归(三服务器矩阵 + 回收站恢复 + 迁移测试)

## 9. 已记录的风险

- 删除不可逆 → 一律先回收站
- 规则变更回溯的误伤 → 不回溯
- 切换任务的静默惊吓 → A+C 策略
- 已有歌单 ownership → provenance + 接管快照 + 唯一映射校验
