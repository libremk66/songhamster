# 进度历史页重构 · 实施方案

> 2026-09-13 讨论稿（未开工）。目标：把「进度历史」从"批次卡片流"改成
> **可搜索、可筛选、能自解释**的排查工具。

## 一、页面骨架

```
┌ 正在运行的任务（实时，不变）
│
├ 标签①全部历史记录      ← 平铺事件表 + 表头筛选 + 搜索卡（内含「流水/批次」视图切换按钮）
├ 标签②各歌单/榜单当前状态 ← 台账（现有"排查用"表增强）
└ 标签③回收站            ← 不变
```

**核心概念三分**（缺一就有黑洞）：

| 视图 | 回答的问题 | 数据源 |
|---|---|---|
| ① 流水（事件） | 发生过什么 | `history_batch` + `history_item` |
| ② 台账（现状） | 现在怎么样 | `current_song_status` + `task_song_ref` + `song_files` |
| ③ 批次摘要 | 这一次跑了什么 | `history_batch` 新增的跳过名单 |

三者的关系：**台账是索引，流水是详情，摘要补空洞**；搜索卡把三者缝在一起。

## 二、数据层

### 2.1 `history_batch` 新增列（创建批次时快照）

| 列 | 类型 | 内容 | 写入时机 |
|---|---|---|---|
| `mode` | TEXT | `incremental` / `mirror` | createBatch |
| `delPolicy` | TEXT | `keep` / `delete` / `archive`（=处理1/2/3） | createBatch |
| `archivePlaylist` | TEXT | 归档歌单名 | createBatch |
| `targetPlaylists` | TEXT | JSON 数组：目标歌单**名字**（不是 id） | 运行开始时（此时已有歌单缓存） |
| `skippedJson` | TEXT | JSON 数组 `[{key,name}]`：本次被 diff 跳过的歌 | 运行结束时 |
| `skippedCount` | INTEGER | 同上计数 | 运行结束时 |

> 快照的理由：任务可被删、配置可被改。现在 `mode`/`delPolicy`/目标歌单只存在
> `sync_task` 上，历史行是"现查"的 → 三个月后回头看会说谎。
> （`taskName`/`taskType`/`trigger` 已经这么做了，照抄。）

### 2.2 `history_item` 新增列（事件行）

| 列 | 类型 | 内容 | 备注 |
|---|---|---|---|
| `action` | TEXT | `in`(入库) / `out`(移出) | 见 2.3 枚举 |
| `process` | TEXT | 处理过程枚举码 | 见 2.3 |
| `filePath` | TEXT | 落盘绝对路径 | **字段已存在但从没写过**（全库 0/80），这次修好 |
| `fileSize` | INTEGER | 字节 | 写历史时快照（文件以后删了就查不到了） |
| `refBefore` | TEXT | JSON `[{taskId,taskName}]` | 操作**前**引用该文件的任务 |
| `refAfter` | TEXT | JSON 同上 | 操作**后** |
| `detail` | TEXT | 保留（人读轨迹，JSON 字符串数组） | 不动 |

**不新增**的字段（改为查询时算，SQLite 窗口函数够用）：
- 「这是第几次处理这首歌」→ `ROW_NUMBER() OVER (PARTITION BY taskId, songKey ORDER BY id)`
- 「全库首次记录」→ `MIN(id) ... GROUP BY songKey`
- 「文件首次下载」→ `song_files.firstDownloadedAt`

### 2.3 处理过程枚举（`action` + `process`）

| action | process | 说明 |
|---|---|---|
| in | `download_new` | 新下载入库 |
| in | `reuse_skip` | 跳过下载入库（本地已有→复用文件） |
| in | `unsatisfied` | 未满足未入库（音质链全试过拿不到） |
| in | `ingest_fail` | 下载成功但媒体库没收录 |
| out | `remove_p1` | 镜像移出·处理1（不删文件） |
| out | `remove_p2` | 镜像移出·处理2（删文件→回收站） |
| out | `remove_p3` | 镜像移出·处理3（移入归档歌单） |
| out | `remove_manual` | 手动删除（历史页/任务列表勾选） |
| out | `chart_out` | 榜单跌出 |

### 2.4 索引

```sql
CREATE INDEX IF NOT EXISTS idx_hi_batch  ON history_item(batchId);
CREATE INDEX IF NOT EXISTS idx_hi_song   ON history_item(songKey, id);
CREATE INDEX IF NOT EXISTS idx_hi_task   ON history_item(taskId, songKey);
CREATE INDEX IF NOT EXISTS idx_hi_status ON history_item(status);
CREATE INDEX IF NOT EXISTS idx_hb_task   ON history_batch(taskId, id);
```

### 2.5 老数据（现有 80 行）

- 新列全部 nullable，老行 → 界面显示 `—（旧记录）`，**不编造**
- 可回填的只有 `filePath`/`fileSize`（文件还在的话，按 `songKey+quality` 从 `song_files` 对）
  → **暂不做**（2026-09-13 决定）：等架构重做上线、确认没问题之后再评估
- `action` 可由 status 反推（success/skipped_dup/unsatisfied→in，removed→out）；
  `process` 反推不可靠（分不清"新下载"和"复用"）→ 老行留空

## 三、写入侧（同步引擎）

1. `createBatch` 传入并写入 2.1 的快照字段
2. 5 处 `insertHistoryItem` 调用统一走包装函数
   `recordEvent({ action, process, fileId?, filePath?, refTaskIdsBefore, ... })`：
   - 自动算 `action`/`process`
   - 自动快照 `fileSize`（fs.statSync，失败则 null）
   - 自动查/写 `refBefore`/`refAfter`
3. 运行结束（`finishBatch` 附近）写 `skippedJson/skippedCount`：
   `songs`（本次歌单全量）减去 `toDownload` 即跳过名单

> 代价：每次运行 +1 次写；每行 +2 次很轻的 SQL。可忽略。

## 四、查询接口

| 路由 | 用途 | 关键参数 |
|---|---|---|
| `GET /api/history/rows` | 标签①表格体（keyset 分页，默认 100 行） | `q` `taskId` `trigger` `mode` `quality` `action` `process` `result` `from` `to` `path` `cursor` |
| `GET /api/history/search?q=` | 搜索卡（按歌聚合：台账+首次+最近+记录数+全部事件行） | `q` |
| `GET /api/history/facets` | 下拉框可选值（任务名/音质/process/结果） | — |
| `GET /api/progress/table` | 标签②台账（**改造现有**） | `onlyIssue=1` |
| `GET /api/history/batch/:id/summary` | 批次摘要（含跳过名单展开） | — |

搜索匹配：`songName` / `singer` LIKE + `sync_task.lxPlaylistName` LIKE（歌单名命中）。
跨全部任务（含榜单订阅、含内部手动下载任务）。

## 五、界面

### 标签①全部历史记录

- 顶部：搜索框（搜歌名/歌手/歌单名，防抖 300ms）+ 快捷筛选（今天 / 近 7 天 / 只看失败 / 只看移出）
- 表格列（12 + 2）：

  | 日期时间 | 所属任务 | 任务属性 | 歌曲名 | 歌手 | 音质 | 操作 | 处理过程 | 结果 | 文件大小 | 文件路径 | 引用情况 | ☑ | 行操作 |

  单元格填法：
  - **任务属性**：`手动 · 增量 · →《华语》`（来自批次快照）
  - **操作**：`入库` / `移出`（色标）
  - **处理过程**：枚举短标签 + `展开` 看完整轨迹（原 detail）
  - **结果**：`✅成功` / `❌失败：原因` / `⏭未满足`
  - **引用情况**：`1 → 2 个任务`（悬停/展开看是哪几个）
  - **行操作**：失败行 `重试`；所有行 `删除`（复用现有三选项弹窗）
- **视图切换按钮「流水 / 批次」**（标签①工具栏上，默认流水；不新增标签）
  - **流水** = 上面的平铺事件表（每首歌一行）
  - **批次** = 每个批次一行：`09-12 14:45 · 华语 · 手动 · 增量 · 处理 3 · 跳过 2 · 移除 1 [展开跳过名单]`
    - 空批次在这里也占一行 → 解决"点开什么都没有"
    - 这里也是"这一次到底跑了什么"的答案
  - 两个视图共用同一套筛选条件与删除逻辑
- 分页：「加载更多」（keyset，按 id 倒序）
- 移动端（<640px）：切成卡片（时间/任务/歌名/状态/处理过程各一行），不做 14 列横滚

### 标签②各歌单/榜单当前状态（原"排查用"折叠块）

- 每个任务一块（playlist + chart + 手动下载都在）
- 表列：歌曲 / 歌手 / 状态 / 音质 / **最后处理** / **记录数→**（点跳标签①并筛该歌）/ **引用数** / 失败原因
- 开关：`只看有问题的（失败/未满足）`
- 顶部提示一行：`本表是"当前状态台账"（按任务×歌曲去重），事件流水见标签①`

### 搜索卡（标签①顶部搜索的产出）

```
笨蛋 · 汪苏泷、五月天 阿信
  当前   《QQ音乐·新歌榜》《QQ·热歌榜》✅ 成功 · flac · 被 2 个任务引用
  文件   54.0 MB · 09-11 07:58 首次下载（来自《QQ·热歌榜》）
  记录   全库 2 条
    #60  09-11 07:58  QQ·热歌榜      下载入库
    #258 09-12 05:18  QQ音乐·新歌榜  复用文件入库
  最近   09-12 14:45 之后未再处理
```

兜底：查不到任何记录的 → `来源不可考（早于记录 / 非本工具下载）`；
已移出的 → `已从《华语》移出（09-12 14:53 · 处理1 · 文件保留）`。

## 七、风险 / 取舍

- **老记录字段缺失**：不编造，统一显式标注"旧记录"
- **事件行长期增长**：分页 + 索引足够；保留策略（如只留 12 个月）暂不做
- **勾选删除逻辑要重写**：现在是"批次框 + 单曲框"两级，平铺后改为"逐行框 + 全选本批"
- **移动端**：14 列不可能塞下 → 卡片化
- **不改同步判定逻辑**：本次只是"多记几个字段 + 换查询/展示"

## 八、已定 / 待定

**已定（2026-09-13）**

1. **标签只做 3 个**：①全部历史记录 ②各歌单/榜单当前状态 ③回收站（没有第 4 个）
2. **移出枚举就三类**：镜像处理1/2/3、手动删除、榜单跌出。
   `process` 存的是字符串码，**以后加类型不用改表结构**，只加一枚枚举值 + 一行显示映射即可
3. **引用情况只统计本工具自己的记录**（不实时查媒体库）
4. **不做批头行/折叠**；批次视角用标签①里的「流水 / 批次」按钮切换
5. **移动端卡片化**
6. **老数据回填推迟**：架构重做上线、确认没问题之后再评估

**只剩实施细节**（不阻塞开工）：筛选控件在表头里的具体排布、批次视图的列取舍、移动端卡片显示哪几个字段
